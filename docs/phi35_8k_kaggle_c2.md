# Phi-3.5 8K C2 Kaggle qualification

This package is a prospective capture executor. It performs neither local
qualification nor local capture. `qualify` uses the pinned model and synthetic
valid token IDs only; it has no dataset/source path. `capture` has no default
and refuses to run unless a separate, reviewed frozen approval is supplied.

1. In Kaggle Notebook, choose **Settings -> Accelerator -> GPU T4 x2**.
2. Turn Internet on only when public model/source downloads are needed.
3. Obtain the exact repository freeze tagged `cascadekv-phi35-8k-kaggle-c2-prep`.
4. Install the repository's locked dependencies, for example `pip install uv && uv sync --frozen --no-dev`.
5. Run `python -m cascadekv.phi35_kaggle_c2 preflight`.
6. Run only `python -m cascadekv.phi35_kaggle_c2 qualify --output /kaggle/working/cascadekv_phi35_8k_capture/qualification.json`.
7. Save that JSON as a notebook output.
8. Stop. Do not invoke `capture` until the qualification JSON is reviewed and a separate immutable approval JSON has been supplied.

The canonical backend is two T4 GPUs, FP16 model computation, SDPA,
`use_cache=false`, GPU-only layer sharding, and no quantization.  FP16 is an
explicit T4 execution decision; it does not claim the checkpoint-native BF16
configuration is being used. Model cache assets use Kaggle's default temporary
cache location. Only durable output is written below
`/kaggle/working/cascadekv_phi35_8k_capture/`.

The approval file is deliberately not generated by the executor. After review,
an authorized freeze process must create exactly this JSON (with the actual
qualification file SHA and backend id):

```json
{"schema_version":"cascadekv-phi35-8k-qualification-approval-v1","review_status":"FROZEN_APPROVED","qualification_sha256":"...","backend_id":"..."}
```

Only then is the explicit command available:

```bash
python -m cascadekv.phi35_kaggle_c2 capture \
  --qualification /kaggle/working/cascadekv_phi35_8k_capture/qualification.json \
  --approved-qualification /kaggle/input/reviewed-qualification/approval.json
```

Capture re-proves and tokenizes only the nine frozen C1 identities. It executes
one 8192-token forward with all five hooks for each source. Valid partial work
is reused only after every existing artifact passes exact provenance, input-ID
hash, SHA, shape, dtype, and backend validation; corrupt or mismatched output
is rejected without overwrite. Raw source text is never written to metadata.
